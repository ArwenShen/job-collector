# 岗位收集器 Side Panel 交互改版 Spec

## 1. 文档状态

- 状态：已完成交互确认，待用户复核书面 Spec
- 日期：2026-09-03
- 变更类型：在既有 Chrome 插件上调整交互与本地岗位管理能力
- 前置 Spec：`docs/superpowers/specs/2026-09-02-job-collector-extension-design.md`
- 视觉参照：用户提供的 JobCollector 右侧面板截图

本 Spec 只覆盖本次交互改版。原 Spec 中四个平台的提取规则、数据字段、CSV 序列化、去重规则、隐私边界和“不做爬虫、不自动投递、不做 AI 托管”等要求继续有效；与本 Spec 冲突的 Popup、备注固定为空、无列表和无单条删除等条款，以本 Spec 为准。

## 2. Objective

将当前点击即消失的小型 Popup 改为 Chrome 原生右侧 Side Panel，让用户在浏览职位详情的同时持续查看已收集岗位。

用户点击 Chrome 工具栏中的“岗位收集器”后，面板出现在浏览器右侧。用户每打开一个支持平台的职位详情页，先点击扩展图标授权并聚焦该页对应的面板，再主动点击一次“收集当前职位”。插件读取当时的激活标签页、保存完整岗位数据，并将岗位加入面板中的紧凑列表。用户可以编辑备注、删除单条记录、撤销刚刚的单条删除，最后统一导出 CSV。

成功意味着：面板不会因为用户点击网页而关闭；收集操作不会使用过期页面数据；列表在有限宽度内清楚展示并可通过 Hover 查看完整字段；备注和删除会可靠同步到本地数据与导出结果。

## 3. Scope changes

### 3.1 新增或替换

- 使用 Chrome 原生 Side Panel 替换 `action.default_popup`。
- 点击扩展工具栏图标时打开 Side Panel。
- 在面板中显示全部已收集职位的紧凑列表。
- 列表增加所属平台、备注和单条删除。
- 允许编辑每条岗位的 `note` 字段。
- 单条删除后提供 5 秒撤销。
- 清空全部使用插件内二次确认，不依赖浏览器原生 `window.confirm`。

### 3.2 保持不变

- 只读取用户当前激活标签页中已经打开的职位详情。
- 每个职位都必须由用户主动点击一次“收集当前职位”。
- 不扫描、遍历或自动点击职位列表。
- 不自动收集后续页面，不读取未打开的职位 URL。
- 四个平台适配器及必需字段校验规则不变。
- 按 `source_site + source_job_id` 去重。
- CSV 的 16 列、字段顺序、BOM、CRLF 和引用规则不变。
- 导出后继续保留本地记录。
- 不增加网络请求、账号、后端、遥测、AI 分析或云同步。

## 4. Chosen approach

采用 Chrome 原生 Side Panel，而不是页面内注入抽屉或加宽 Popup。

原因：

- Side Panel 在用户操作职位页面时可以保持打开，符合连续浏览、逐条主动收集的使用路径。
- 扩展 UI 与招聘网站 DOM、CSS 和脚本隔离，减少四个平台页面更新造成的样式冲突。
- 同一个面板可以持续呈现本地记录、编辑备注和导出，不需要在每次打开 Popup 时恢复临时 UI 状态。

页面内抽屉不采用，因为它需要侵入招聘网站页面且容易产生层级、布局和样式冲突。继续使用 Popup 不采用，因为用户点击网页后 Popup 会关闭。

## 5. Manifest and runtime architecture

### 5.1 Manifest V3

Manifest 权限调整为：

```json
{
  "permissions": ["activeTab", "scripting", "storage", "sidePanel"]
}
```

- 保留 `activeTab`、`scripting` 和 `storage`。
- 新增 `sidePanel`，用于显示 Chrome 原生右侧面板。
- `action` 保留标题，但移除 `default_popup`。
- 增加扩展后台 service worker。
- 增加 `side_panel.default_path`，指向 Side Panel 页面。
- 不新增静态 host permissions、`tabs`、`downloads`、Cookie 或浏览历史权限。

### 5.2 打开方式

后台 service worker 初始化：

```ts
chrome.sidePanel.setPanelBehavior({ openPanelOnActionClick: true });
```

用户点击工具栏扩展图标时，Chrome 打开或聚焦 Side Panel，同时通过 `activeTab` 授权当前标签页。用户通过 Chrome 自带关闭按钮关闭面板。

为了避免申请四个平台的长期站点访问权限：

- 用户切换到新的标签页后，必须在该标签页再次点击一次扩展图标，再点击面板中的收集按钮。
- 用户跨站导航导致 `activeTab` 授权失效时，也必须再次点击扩展图标。
- 同一标签页、同一站点内切换职位后，收集按钮仍会重新提取当前页面；如果 Chrome 已撤销授权，则显示明确提示，引导用户重新点击扩展图标。
- Side Panel 已打开时，再次点击扩展图标只负责授权当前页并聚焦现有面板，不创建第二个面板。

### 5.3 核心数据流

```text
点击扩展图标
→ 打开 Side Panel
→ activeTab 授权当前标签页
→ 立即读取本地岗位列表
→ 用户在当前标签页浏览职位详情
→ 点击“收集当前职位”
→ 此刻重新查询当前窗口的激活标签页
→ 注入既有 content extraction bundle
→ 校验平台、详情页与必需字段
→ 按唯一键新增或覆盖记录
→ 刷新列表和操作反馈
```

面板初始化时不缓存一个可长期使用的 `currentRecord`。每次点击“收集当前职位”都必须重新查询并提取当前激活标签页，避免用户保持面板开启并切换职位后误收集旧岗位。切换到新标签页或跨站导航后，由用户再次点击扩展图标恢复 `activeTab` 授权；插件不通过扩大 host permissions 绕过这一显式授权动作。

## 6. Side Panel information architecture

从上到下固定为：

1. 标题栏：产品名称“岗位收集器”；关闭按钮由 Chrome 提供。
2. 主按钮：“收集当前职位”。
3. 数量摘要：“已收集 N 个职位”。
4. 临时反馈区域：成功、更新、错误或撤销信息；没有反馈时不占用明显空间。
5. 已收集岗位列表：占据剩余高度并独立纵向滚动。
6. 底部操作：“导出 CSV”和“清空”。

顶部收集按钮和底部操作始终可见，长列表只在中间区域滚动。不增加搜索、筛选、标签、统计卡、当前职位预览卡或其他常驻控件。

## 7. Job list

### 7.1 Columns

列顺序固定为：

```text
# / 平台 / 公司 / 职位 / 薪资 / 备注 / 删除
```

- `#`：当前显示顺序，两位数字起步，如 `01`、`02`。
- `平台`：列表中显示 `BOSS`、`猎聘`、`智联`、`前程`；完整名称分别为 BOSS直聘、猎聘、智联招聘、前程无忧。
- `公司`：`company_name`。
- `职位`：`job_title`。
- `薪资`：`salary`。
- `备注`：无备注时显示“添加”；有备注时显示可辨识的截断文本。
- `删除`：只显示紧凑删除图标，并提供明确的无障碍名称。

职位文字不在本次改版中承担导航功能，不新增“打开原职位”动作。

### 7.2 Ordering and updates

- 新收集的唯一岗位追加到列表底部。
- 列表按首次写入顺序稳定展示。
- 重复收集同一岗位时整条更新，数量不增加，原列表位置不改变。
- 删除或撤销后重新计算显示序号。
- 浏览器或面板重启后顺序必须保持一致。

如果现有存储结构不足以稳定表达首次写入顺序，可以增加不进入 CSV 的本地元数据；不得改变 CSV 列或向 CSV 泄漏内部排序字段。

### 7.3 Truncation and Hover

- 平台、公司、职位、薪资和备注单元格均保持单行。
- 内容超出列宽时使用省略号，列表不得出现横向滚动条。
- 鼠标 Hover 或键盘聚焦可交互单元格时显示完整内容。
- Tooltip 必须留在可视区域内，不能被 Side Panel 边界裁切。
- 空字段显示 `—`，其 Tooltip 显示“暂无信息”。
- `#` 和删除按钮不显示字段 Tooltip。

Side Panel 变窄时，优先保证收集、备注和删除操作可用；文本列通过缩短可见内容适配，不隐藏任何一列。

## 8. Collection behavior

### 8.1 Success

- 新岗位保存成功后追加一行。
- 数量加一。
- 显示“已收集当前职位”。

### 8.2 Duplicate

- 唯一键仍为 `${source_site}:${source_job_id}`。
- 再次收集时使用最新提取结果覆盖岗位字段和 `collected_at`。
- 已编辑的 `note` 不得被新的页面提取结果清空或覆盖。
- 数量和原列表位置不变。
- 显示“已更新当前职位，没有新增重复记录”。

### 8.3 Unsupported and failed states

- 当前网站不支持或当前页面不是职位详情页：显示“请打开支持平台的职位详情页”。
- 缺少 `job_title` 或 `job_description`：禁止保存，并提示缺少的必需字段。
- 没有可注入的标签页或 Chrome 内置页面：显示“无法读取当前页面，请打开职位详情后重试”。
- `activeTab` 授权不足：显示“请在当前职位页再次点击扩展图标后重试”。
- 任一收集错误都不能清空或遮挡既有列表，导出、备注和删除仍然可用。

## 9. Notes

- 点击“添加”或已有备注文字，打开紧凑备注编辑浮层。
- 编辑框加载当前备注；支持保存和取消。
- 备注允许为空，最多 200 个字符。
- 保存前移除首尾空白，保留正文内部换行。
- 保存成功后更新本地 `JobRecord.note`，并刷新列表显示。
- 点击取消、按 `Escape` 或点击浮层外部时放弃未保存修改。
- 保存失败时保留编辑内容并显示错误，允许再次保存。
- 导出 CSV 时读取保存后的 `note` 原文。

备注仅存储在 `chrome.storage.local`，不写回招聘平台，不发往网络。

## 10. Single delete and undo

- 点击某行删除按钮后，立即从本地岗位集合和列表中删除该记录。
- 面板显示“已删除 1 个职位 · 撤销”，撤销入口保留 5 秒。
- 5 秒内点击撤销，必须完整恢复删除前的岗位记录、备注和列表位置。
- 新的删除操作发生时，上一条未撤销删除立即结束撤销窗口；每次只保留一个可撤销项。
- 面板关闭、刷新、浏览器退出或 5 秒到期后，不保证继续撤销。
- 删除失败时保留原记录，并显示错误。

撤销所需记录和原位置可暂存在 Side Panel 内存中；删除本身必须立即持久化，不能等撤销窗口结束后才写入。

## 11. Clear all

- “清空”在没有记录时禁用。
- 点击后打开插件内确认对话框，明确显示即将删除的岗位数量。
- 用户取消、按 `Escape` 或关闭对话框时不得修改数据。
- 用户确认后清空全部记录和备注，将数量更新为 0，并禁用导出与清空。
- 清空全部不提供撤销。
- 不使用浏览器原生 `window.confirm`，以保证键盘行为、自动化测试和真实浏览器表现一致。

## 12. Export

- “导出 CSV”在没有记录时禁用。
- 导出仍使用原 Spec 定义的 16 列和序列化规则。
- `note` 改为导出用户保存的备注，不再固定为空字符串。
- 行顺序与 Side Panel 列表顺序一致。
- 导出成功或失败都不修改本地记录。
- 不申请 `downloads` 权限，继续通过浏览器端 Blob 和下载链接生成文件。

## 13. Visual design

用户截图作为右侧布局、紧凑列表和操作位置的参照，不逐项复制其中未确认的装饰和功能。

继续从 `docs/design/DESIGN.md` 中摘取适合插件界面的既有规则：

- Side Panel 画布使用 Deep Iris `#16165c`。
- 列表与浮层使用 Iris Shadow `#232269`。
- 主按钮使用 Iris Pulse `#5350cc`。
- 主文字 `#ffffff`，次级文字 `#d8d8e3`，弱化文字 `#9494a9`。
- 提示和可交互文本使用 Cyan Soft `#59b4ff`。
- 错误与危险操作使用清晰、克制且满足对比度的红色，不复用 Mint Vital。
- 采用系统无衬线字体，500/600 字重；不加载远程字体。
- 以 8px 为主要间距节奏；列表和面板控件使用适合窄界面的 12–16px 圆角；主按钮保持胶囊形。
- 不引入插画、渐变、纹理、图表、装饰图标或动画。

`docs/design/style-dna.md` 的 16:9 正文配图和手绘插画规则不适用于浏览器工具面板，不纳入实现。

## 14. Accessibility

- 所有按钮、备注编辑和确认对话框必须可通过键盘操作。
- 使用明确的焦点轮廓，不只依赖颜色表达状态。
- Tooltip 对 Hover 和键盘焦点均可访问；完整文本不能只对鼠标用户开放。
- 备注浮层打开后将焦点移入编辑框，关闭后将焦点还给触发按钮。
- 清空确认对话框打开时约束焦点；关闭后将焦点还给“清空”。
- 删除按钮的无障碍名称包含岗位名称，例如“删除：AI 产品经理”。
- 成功、错误和撤销反馈通过适当的 live region 宣告，但不得反复朗读整个列表。

## 15. Storage changes and compatibility

现有 `JobRecord` 与 CSV schema 版本保持不变。仓库新增能力：

- 更新指定记录的 `note`。
- 删除指定唯一键的记录。
- 恢复被删除记录到原显示位置。
- 稳定保留首次写入顺序。

升级扩展后，现有 `jobCollector.records.v1` 数据必须继续可读，无需用户手动迁移。旧记录没有额外排序元数据时，按读取到的既有顺序初始化；迁移不得丢失岗位字段或改变 CSV 唯一键。

## 16. Test strategy

### 16.1 Unit tests

- Manifest 包含 `sidePanel`、service worker 和 `side_panel.default_path`，且不再包含 `default_popup`。
- 后台行为配置为点击扩展图标打开 Side Panel。
- 点击收集时每次调用一次最新的 active-tab extraction，而不是复用初始化缓存。
- 新岗位追加；重复岗位更新但不增数、不换位且保留备注。
- 列表的平台简称、空值、截断属性和完整 Tooltip 内容正确。
- 备注保存、取消、清空备注、200 字边界和失败重试正确。
- 单条删除立即持久化；5 秒内撤销恢复完整记录和原位置；超时后不能撤销。
- 清空确认的确认、取消和 `Escape` 路径正确。
- 导出读取最新备注并保持列表顺序。
- 既有四平台提取器与 CSV 测试继续全部通过。

### 16.2 Build verification

- `npm test`
- `npm run build`
- `dist/manifest.json`、Side Panel 页面、后台脚本和 content bundle 均存在。
- 构建产物不包含远程脚本、远程字体或未批准权限。

### 16.3 Real Chrome acceptance

在 Chrome 加载最新 `dist/` 后验证：

1. 点击扩展图标，在右侧打开 Side Panel，而不是 Popup。
2. 打开任一真实支持平台职位详情，点击收集后出现正确平台、公司、职位和薪资。
3. 保持面板开启，在同一标签页、同一平台切换到另一个详情页后再次收集，新增的是新页面岗位而非旧岗位。
4. 切换到新标签页或另一个平台时，再次点击扩展图标授权当前页，然后能够收集该页岗位。
5. 在四个平台各收集至少一个岗位，平台简称和字段正确。
6. Hover 和键盘聚焦每个数据列时可查看完整内容，且 Tooltip 不越界。
7. 重复收集同一岗位，数量不变、位置不变、已有备注不丢失。
8. 编辑备注并导出，CSV 的 `note` 单元格与保存内容一致。
9. 删除一条后数量减少；5 秒内撤销后记录、备注和位置恢复。
10. 再次删除并等待超过 5 秒，撤销入口消失且重开面板后记录仍已删除。
11. 点击清空后取消，数据保持不变；确认后全部清空。
12. 收集、备注、删除和导出失败状态不会破坏既有列表。
13. 导出的 CSV 仍满足 16 列、UTF-8 BOM、CRLF、全字段双引号及 JD 完整性要求。

## 17. Acceptance criteria

只有以下条件全部满足，本次改版才可验收：

- 点击扩展图标可稳定打开 Chrome 原生右侧面板。
- 用户操作招聘页面时面板保持打开。
- 切换到新标签页或跨平台页面后，再次点击扩展图标可以授权当前页并复用现有面板。
- 每次收集都以点击当下的激活标签页为准。
- 列表完整包含 `# / 平台 / 公司 / 职位 / 薪资 / 备注 / 删除`。
- 各数据列超长文本被截断，并可通过 Hover 和键盘焦点查看完整值。
- 新增、重复更新、备注、单条删除、5 秒撤销和清空全部行为符合本 Spec。
- 重复更新不会清空用户备注。
- CSV 合约不变，备注正确导出，完整 JD 不受列表摘要影响。
- 现有本地记录升级后仍可读取和导出。
- 四个平台提取测试、存储测试、Side Panel 交互测试和构建全部通过。
- 插件仍不自动遍历、自动收集、自动投递、访问后端或执行 AI 托管。
