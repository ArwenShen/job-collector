AI 方案设计

Skill 设计能力(8/10)

能力结论：由于 Skill 要编排高难度知识与权限 Tool 并处理委派、验证和降级，难度较高，需要候选人能设计可复用、可治理且可恢复的专业能力。

来源事实

  • JD 要求判断哪些程序性知识应做成 Skill，并建立 Skill 撰写规范与版本治理。
  • JD 同时要求设计主子 Agent 委派、知识检索、Tool 权限和失败降级。

隐含任务

  • 把教育领域方法设计成 Agent 可自主选择步骤的 Skill。
  • 编排 Skill 对知识库和受控 Tool 的调用、上下文传递、失败恢复与结果验证。

难度驱动因素

  • Skill 自身需要处理主子 Agent 分工、上下文隔离、版本治理和开放式判断。
  • 同一核心任务直接依赖高难度知识库治理和受权限约束的 Tool，抬高了 Skill 的编排下限。
  • 委派简报失真、知识过时和过度自信要求在 Skill 层提供验证与降级。

需要避免：避免把 Skill 写成静态提示词，缺少输入输出契约、依赖治理、失败处理和版本兼容。

知识库设计能力(8/10)

能力结论：由于教育知识规模大、形态异构且需要在 Skill 与检索库之间治理版本和过期问题，要求很高，需要候选人能设计可更新、可追溯的知识供给体系。

来源事实

  • JD 明确区分程序性知识与陈述性、海量、碎片化知识，并要求在 Skill 和检索库之间做选择。
  • JD 要求处理知识过时并建立撰写规范与版本治理。
  • 作业帮的 AI 学习产品依赖多学科、多学段题库、教材和教研内容。

隐含任务

  • 设计教育知识的 Skill 化、检索化和版本化边界。
  • 建立来源、更新、冲突、过期和检索有效性的治理机制。

难度驱动因素

  • 知识覆盖多学科、多学段和多种内容形态，并同时包含事实性资料与程序性教研方法。
  • 知识规模大且碎片化，需要处理检索、版本、过期和跨内容综合。
  • 知识错误会沿 Agent 学习辅导链路影响学生理解和后续练习。

需要避免：避免把所有知识统一塞入 RAG，忽略程序性方法、版本冲突、权威来源和过期治理。

Agent Tool 设计(7/10)

能力结论：由于 Tool 调用涉及多 Agent 权限传递、人工确认和自治分级，难度较高，需要候选人能设计安全契约、护栏和失败接管机制。

来源事实

  • JD 要求决定 Agent 可调用哪些工具、哪些动作必须经过人类确认。
  • JD 要求把 Agent 自治程度设计为产品化分级，并为失败类型配置产品护栏。

隐含任务

  • 定义 Tool 输入输出、权限主体、确认规则和失败反馈。
  • 按动作风险划分自治等级并设计人工接管与审计策略。

难度驱动因素

  • Tool 能力与自治等级直接耦合，需要按动作风险决定自动执行或人工确认。
  • 主子 Agent 委派增加了权限传递、调用归属和失败追踪复杂度。
  • 面向学习用户的错误工具调用需要护栏和降级，公开资料未给出具体高影响写操作。

需要避免：避免只定义函数参数而没有授权、确认、审计、异常和人工接管规则。

工作流设计(6/10)

能力结论：由于失败治理包含多类触发、降级、人工确认和恢复分支，难度中等，需要候选人能设计可观测且可回归的状态流程。

来源事实

  • JD 要求规定哪些任务留在主线、哪些派发给子 Agent，以及失败时如何降级。
  • 岗位需要为上下文溢出、委派失真、知识过时和过度自信分别设计产品护栏。

隐含任务

  • 定义失败检测、降级、人工确认、恢复和结果回传的状态流程。
  • 为不同失败类型配置明确分支和回归检查。

难度驱动因素

  • 失败治理流程包含多类触发条件、降级分支、人工节点和恢复结果。
  • 工作流需要与主子 Agent 的执行轨迹衔接，但 JD 没有呈现长链审批或跨系统补偿。

需要避免：避免把需要严格触发和恢复的失败流程混同为允许 Agent 自由判断的 Skill。

记忆能力(4/10)

能力结论：由于当前任务主要处理短周期上下文隔离而长期状态约束有限，难度较低，需要候选人能定义基础的上下文保留、压缩和失效规则。

来源事实

  • JD 强调上下文窗口是稀缺资源，并要求设计主线与子 Agent 的上下文隔离。
  • JD 将上下文溢出和委派简报失真列为 Agent 失败类型。

隐含任务

  • 定义任务上下文的保留、压缩、隔离和失效规则。
  • 区分当前任务上下文、委派摘要和可长期保留的用户状态。

难度驱动因素

  • 已确认任务聚焦单次或多步执行中的上下文资源管理，作用周期较短。
  • 主子 Agent 间需要控制上下文传递和摘要失真，但长期用户记忆对象与更正机制没有进入岗位职责。

需要避免：避免把上下文窗口、业务数据库和长期用户记忆混为同一种状态机制。

Demo 原型设计(6/10)

能力结论：由于原型要联动多 Agent、知识、Tool 和评测并完成轨迹驱动迭代，难度中等，需要候选人能构建可运行且可比较版本的 Agent Demo。

来源事实

  • JD 要求候选人亲手写过 prompt 或系统提示词并完成至少一个完整版本周期。
  • JD 要求候选人能读取 Agent trace，并把被他人实际使用的 Skill、Tool 定义或 Agent 配置列为加分项。

隐含任务

  • 用可运行原型验证主子 Agent 委派、Tool 确认和失败降级。
  • 通过 trace 和评估集比较提示词、Skill 与护栏版本。

难度驱动因素

  • 原型需要覆盖多 Agent、知识、Tool、权限和评测多个联动假设。
  • 验证不止展示交互，还要保留执行轨迹并完成至少一个迭代周期。
  • 生产部署与真实业务系统接入范围没有在 JD 中展开。

需要避免：避免只做顺利路径演示而不验证权限、异常、降级和版本差异。

硬实力

需求与定义(7/10)

能力结论：由于岗位要在多类教育场景和多种 Agent 机制之间定义行为与验收边界，难度较高，需要候选人能把不确定行为转化为可执行的产品规则。

来源事实

  • JD 将岗位职责拆为能力边界、知识供给、工具权限、评估体系和失败模式五类设计对象。
  • 作业帮 App 同时覆盖答疑、批改、练习、写作和志愿填报等多类学习场景。

隐含任务

  • 定义各学习场景中主 Agent、子 Agent、知识与 Tool 的产品边界。
  • 把行为是否得体转化为可验收的产品要求和缺陷标准。

难度驱动因素

  • 需要在多类学习场景、学生与家长角色及 Agent 多组件之间划定边界。
  • 需求对象包含询问、停止、委派、权限和降级等非确定性行为，验收标准难以沿用普通功能正确性。

需要避免：避免只写技术模块清单而没有用户场景、行为边界、例外条件和验收标准。

AI 方案设计(7/10)

能力结论：由于六类 AI 方案组件需要耦合并共同满足权限、上下文和行为质量约束，难度较高，需要候选人能设计可验证且可降级的整体 Agent 方案。

来源事实

  • JD 同时要求设计多 Agent 委派、Skill 与检索知识、Tool 权限、评测和失败护栏。
  • 作业帮已将教育大模型能力规划到 App、智能硬件、智能图书和教育数字化等多种业务场景。

隐含任务

  • 把 Skill、知识库、Tool、工作流、上下文和评测机制组合为可控 Agent 方案。
  • 在教育产品中验证方案的任务完成质量、行为得体性和失败恢复。

难度驱动因素

  • Skill、知识、Tool 和评测彼此耦合，单一组件失真会沿委派链影响最终学习结果。
  • 方案需同时处理自主判断、权限控制、上下文稀缺、版本治理和失败降级。

需要避免：避免把大模型、RAG 和 Tool 简单拼装，忽略组件间契约、风险边界和可验证性。

开发与落地(6/10)

能力结论：由于多个 Agent 组件需要按版本联动并通过执行轨迹闭环验证，难度中等，需要候选人能协调产品设计、配置迭代和工程验收。

来源事实

  • JD 要求候选人亲手迭代过至少一个完整提示词版本周期并能读取 Agent 执行轨迹。
  • 岗位需要建立 Skill 撰写规范、版本治理和产品级护栏。

隐含任务

  • 推动提示词、Skill、Tool 权限、评测集与护栏按版本联动交付。
  • 用 trace 定位产品问题并把结论反馈给产品和工程实现。

难度驱动因素

  • 交付对象跨提示词、配置、知识、Tool、评测和护栏多个组件，需要保持版本一致。
  • 完整版本周期要求从设计、观测到回归验证形成闭环，但公开职责未呈现复杂部署环境。

需要避免：避免只验收最终回答而忽略执行轨迹、配置版本、降级路径和回归结果。

来源：[引用1]

评测与迭代(8/10)

能力结论：由于评测需覆盖多步轨迹、开放式行为标准和面向未成年学习用户的质量风险，要求很高，需要候选人能建立可归因、可回归的 Agent 评测体系。

来源事实

  • JD 明确要求建立行为是否得体的评估方法，而非只判断功能正确性。
  • JD 列出询问时机、停止条件、委派简报、上下文溢出、知识过时和过度自信等失败类型。
  • JD 要求候选人能读取 Agent trace 并从执行过程中定位产品问题。

隐含任务

  • 建设覆盖多场景行为、失败类型和护栏效果的评估集。
  • 把 trace、人工判断和产品指标组合为持续迭代闭环。

难度驱动因素

  • 评测对象是开放式 Agent 行为，包含时机、分寸、委派质量和可信度等多维主观标准。
  • 需要从最终输出下钻到多步执行轨迹，并把失败归因到上下文、知识、Tool 或委派环节。
  • 教育用户包含未成年人，错误建议与过度自信对学习判断和产品信任的影响较大。

需要避免：避免只用单轮答案正确率覆盖 Agent 的过程质量、安全边界和长期回归。

来源：[引用1]、[引用2]、[引用4]

增长与商业化(3/10)

能力结论：由于岗位公开职责仅涉及自治程度的产品分级而商业链路范围有限，难度较低，需要候选人能把技术分层翻译为基础的用户价值与权益边界。

来源事实

  • 作业帮 App 面向个人用户提供免费功能与 VIP 订阅服务。
  • JD 要求把 Agent 自治程度设计为产品化分级。

隐含任务

  • 解释不同自治等级对学生和家长的价值与风险差异。
  • 评估 Agent 能力分层是否支持清晰的产品权益表达。

难度驱动因素

  • 当前职责只明确自治程度分级，未形成多市场、多渠道或复杂定价链路。
  • 用户价值仍需与安全边界结合表达，但商业化任务范围有限。

需要避免：避免把技术自治等级直接包装成付费权益而没有用户价值和安全依据。

软实力

沟通力(6/10)

能力结论：由于岗位要跨产品与工程语境解释多组易混概念并形成团队规范，难度中等，需要候选人能用案例和边界条件推动共同理解。

来源事实

  • JD 要求候选人在不依赖工程师的情况下讲清子 Agent 与传统垂类 Bot、Skill 与 RAG、上下文窗口的产品含义。
  • 岗位需要制定可被他人使用的 Skill 撰写规范、Tool 定义和 Agent 配置。

隐含任务

  • 在产品、工程和业务语言之间解释 Agent 架构取舍。
  • 把边界、权限、失败和评测规则写成可执行规范。

难度驱动因素

  • 沟通内容跨产品概念、Agent 技术机制和教育业务行为，需要避免术语歧义。
  • 规范将被多角色执行，表达必须同时支持设计、开发和验收。

需要避免：避免用概念口号代替真实案例、边界条件和可执行规则。

来源：[引用1]

创新能力(8/10)

能力结论：由于 Agent 产品范式、行为评测和失败治理都缺少完全成熟的方法，难度较高，需要候选人能用真实实验建立并修正新的产品框架。

来源事实

  • JD 强调从传统意图槽位对话系统迁移到 Agent 新范式，并要求说明旧直觉如何被推翻。
  • 岗位要为不确定性产品建立行为评测、失败分类和自治程度分级。

隐含任务

  • 在缺少成熟范式时提出 Agent 产品边界、失败模型和验证方法。
  • 通过真实版本迭代修正旧有对话产品方法。

难度驱动因素

  • 问题同时包含新技术机制、开放式行为质量和尚未稳定的产品方法。
  • 岗位需要原创失败分类与护栏，而不是套用传统功能测试或固定意图流程。

需要避免：避免把传统对话 Bot 的确定性流程原样迁移到具备自主判断的 Agent。

来源：[引用1]

执行能力(6/10)

能力结论：由于多个 Agent 组件需要按依赖推进并在版本周期内持续回归，难度中等，需要候选人能组织并闭环多条相互关联的产品任务。

来源事实

  • 岗位需要同时推进能力边界、知识治理、Tool 权限、评测和失败护栏。
  • JD 要求候选人亲手完成至少一个提示词版本周期并能通过 trace 定位问题。

隐含任务

  • 安排多个 Agent 机制的设计、试验、回归和版本依赖。
  • 把轨迹问题快速转化为提示词、知识、Tool 或护栏改动。

难度驱动因素

  • 多条任务线共享同一 Agent 运行链路，变更之间存在回归依赖。
  • 版本迭代需要同步评测集、配置、知识和失败策略，但没有证据显示存在超长组织链路。

需要避免：避免各组件独立迭代导致版本不一致、问题无法复现或护栏失效。

来源：[引用1]
