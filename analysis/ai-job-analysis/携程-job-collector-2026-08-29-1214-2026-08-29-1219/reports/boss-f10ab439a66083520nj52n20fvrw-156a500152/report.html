AI 方案设计

Skill 设计能力(8/10)

能力结论：由于旅行 Skill 需综合高难度实时知识、交易 Tool 和记忆并支持自主任务选择，难度较高，需要候选人能设计可靠的领域能力编排。

来源事实

  • 岗位直接负责 Skill、任务规划、Tool、Memory 和多 Agent 协同。
  • 产品需要完成旅行问答、推荐、规划和交易衔接等不同领域任务。

隐含任务

  • 定义旅行 Skill 的适用场景、选择条件、上下文和结果验证。
  • 编排实时知识、用户记忆与预订工具依赖。

难度驱动因素

  • Agent 需根据旅行阶段和用户约束自主选择搜索、规划或服务方法。
  • 直接依赖的知识库与 Tool 均达到高难度，增加时效、权限和结果验证负担。
  • 记忆和多 Agent 协作进一步增加上下文传递与失败归因复杂度。

需要避免：避免按旅行品类堆叠提示词，缺少 Skill 选择边界、依赖契约和可验证结果。

知识库设计能力(8/10)

能力结论：由于旅行知识高度异构、全球化且包含持续变化的库存价格与规则，难度较高，需要候选人能设计实时、可信且可追溯的知识方案。

来源事实

  • 产品整合目的地、榜单、点评、行程、库存、价格和旅行规则。
  • 年报明确提示 AI 旅行信息可能出现不完整、错误或过期风险。

隐含任务

  • 定义静态旅行内容与实时库存价格的检索和引用策略。
  • 处理来源时效、冲突、地域语言与结果可追溯性。

难度驱动因素

  • 知识来源跨结构化库存、规则、用户点评和目的地内容。
  • 价格、可用性、航班状态和政策持续变化。
  • 多语言和全球目的地扩大知识异构性。
  • 错误知识会直接影响预订决策和行程安排。

需要避免：避免把模型记忆当作实时事实源，忽略时间戳、来源、冲突和可预订性验证。

Agent Tool 设计(8/10)

能力结论：由于 Tool 横跨实时旅行库存和有交易副作用的订单链路且失败会传播，难度较高，需要候选人能设计安全、可确认且可恢复的工具体系。

来源事实

  • 岗位直接负责工具调用与 CLI，产品需连接搜索筛选、行程保存和预订结果。
  • 集团正在推进复杂多步骤的 Agentic 搜索与预订。

隐含任务

  • 定义搜索、筛选、保存、提醒与预订 Tool 的契约和调用条件。
  • 设计价格变化、库存失效、重复执行和交易确认的异常处理。

难度驱动因素

  • 工具横跨多类旅行商品、库存、订单和行程系统。
  • 实时价格与可用性可能在对话和执行之间变化。
  • 预订相关操作具有资金与订单副作用，需要确认和审计。
  • 多步骤调用失败会改变后续行程规划。

需要避免：避免只验证 API 返回，遗漏价格二次确认、幂等、权限、失败补偿和人工接管。

工作流设计(8/10)

能力结论：由于旅行工作流跨多轮、多状态、交易确认和长期行程服务并包含重新规划分支，难度较高，需要候选人能设计可恢复的会话编排体系。

来源事实

  • 岗位直接负责意图识别、状态追踪、上下文管理和对话恢复。
  • 旅行流程从信息收集、方案比较延伸到预订、提醒与售后。

隐含任务

  • 设计旅行会话状态、槽位、分支、确认、暂停和恢复逻辑。
  • 处理多人协作、行程变更和售后转接流程。

难度驱动因素

  • 多轮会话包含缺失条件追问、方案比较、用户确认和交易跳转。
  • 库存变化与用户修改会使流程回退或重新规划。
  • 行程保存、协作、提醒和售后跨越较长时间状态。
  • 多 Agent 协同要求明确任务移交与共享状态。

需要避免：避免只设计线性对话脚本，导致条件变化、跨会话恢复和多 Agent 移交时状态错乱。

记忆能力(7/10)

能力结论：由于跨会话行程与用户偏好直接影响后续决策且存在过期冲突风险，难度较高，需要候选人能设计分层、可更新的旅行记忆机制。

来源事实

  • 岗位直接负责记忆管理与上下文。
  • TripGenie 可保存结构化行程以供后续继续细化，并依据用户偏好调整结果。

隐含任务

  • 区分会话状态、行程事实、长期偏好和同行人协作信息。
  • 定义记忆写入、召回、更新和过期规则。

难度驱动因素

  • 旅行规划跨多次会话且结果依赖已选日期、地点、预算和预订状态。
  • 偏好、同行人意见与真实订单具有不同可信度和生命周期。
  • 过期记忆可能触发错误推荐或与当前行程冲突。

需要避免：避免把全部历史对话长期保留，缺少事实更新、偏好置信度、删除和隐私边界。

Demo 原型设计(8/10)

能力结论：由于原型需连接真实旅行数据与工具并验证多轮状态、记忆和异常恢复，难度较高，需要候选人能构建支撑上线决策的高保真 Agent Demo。

来源事实

  • 岗位负责 0→1 对话产品，并需输出原型、交互规范和验收标准。
  • 岗位要求对接模型、Prompt、Skill、CLI 和评测完成方案闭环。

隐含任务

  • 连接真实旅行数据、模型和搜索工具制作高保真多轮原型。
  • 模拟缺失条件、库存变化、工具失败、恢复和交易确认。

难度驱动因素

  • 原型需要同时验证语言交互、实时旅行数据和工具执行。
  • 多轮状态、记忆与多 Agent 协作必须在真实任务中联合测试。
  • 原型结果直接支撑架构、交互和上线验收决策。

需要避免：避免只演示理想问答，掩盖实时数据变化、工具失败和状态恢复问题。

硬实力

需求与定义(8/10)

能力结论：由于全球旅行者需求异构、旅程阶段多且结果受实时交易约束，难度较高，需要候选人能定义完整的对话旅行产品与任务边界。

来源事实

  • 产品服务全球旅行者并覆盖灵感、规划、预订、行中与售后阶段。
  • 岗位需要从 0 到 1 定义智能助手、多轮机器人和 Agent 产品架构。

隐含任务

  • 拆解不同旅程阶段、用户约束和旅行商品的对话需求。
  • 定义助手、搜索预订工具与原有 App 页面之间的产品边界。

难度驱动因素

  • 用户语言、目的地、预算、同行人和偏好高度多样。
  • 机票、酒店、景点与行程规划的决策条件和变化节奏不同。
  • 需求结果需要连接真实库存、价格、规则和交易页面。

需要避免：避免把旅行需求简化为通用问答，遗漏实时约束、用户决策阶段和可执行结果。

AI 方案设计(8/10)

能力结论：由于多类 Agent 机制强耦合并受到实时数据、交易可靠性和恢复约束，难度较高，需要候选人能设计完整的对话旅行解决方案。

来源事实

  • 岗位直接负责 Harness、任务规划、Tool、Skill、记忆、多 Agent、状态追踪和恢复。
  • 产品需把旅行内容、用户偏好和实时可预订结果组合为端到端服务。

隐含任务

  • 设计多轮旅行 Agent 的规划、知识、工具、记忆与工作流体系。
  • 处理事实准确性、交易控制和异常恢复。

难度驱动因素

  • 六类 Agent 机制强耦合并共同决定旅行任务是否完成。
  • 知识与库存持续变化，工具结果会改变后续规划状态。
  • 预订相关动作带来价格、规则、权限和错误后果约束。

需要避免：避免只优化模型回答，忽略知识 grounding、工具执行、状态连续性和交易控制。

开发与落地(8/10)

能力结论：由于产品跨模型、搜索、库存、交易和多语言客户端且依赖复杂，难度较高，需要候选人能推动对话 Agent 在真实旅行链路中稳定上线。

来源事实

  • 岗位需要联动研发、算法和运营完成产品落地与迭代。
  • TripGenie 已嵌入移动 App 并连接旅行搜索、行程和预订页面。

隐含任务

  • 推动模型、会话引擎、旅行搜索、库存与交易系统协同上线。
  • 制定 PRD、原型、交互规范和验收标准。

难度驱动因素

  • Agent 依赖模型、内容、搜索、库存、订单和客户端多个系统类别。
  • 实时价格与可用性变化要求端到端数据和交互保持一致。
  • 多语言与全球市场扩大了测试、发布和运营协作范围。

需要避免：避免只验收对话界面，忽略搜索、库存、订单和行程状态的端到端一致性。

评测与迭代(8/10)

能力结论：由于评测对象跨多语言旅行场景和多系统链路且错误会影响真实交易，难度较高，需要候选人能建设端到端评测与 badcase 归因闭环。

来源事实

  • 岗位要求建立效果评测并对 badcase 做闭环优化。
  • AI 输出可能涉及行程、库存、票价规则和取消政策等高时效旅行信息。

隐含任务

  • 分层评测意图、规划、事实、Tool、对话状态和最终任务结果。
  • 结合线上行为、订单转化和 badcase 定位问题来源。

难度驱动因素

  • 旅行任务覆盖多语言、多商品和多个旅程阶段，样本异构。
  • 失败可能来自模型、知识时效、Tool、库存变化或对话状态。
  • 错误信息可能影响真实购买决策、行程安排和用户信任。

需要避免：避免只看语言流畅度，遗漏事实准确、工具执行、状态恢复和交易后果。

增长与商业化(8/10)

能力结论：由于 AI 助手贯穿全球多品类旅行决策并直接影响订单转化与长期信任，难度较高，需要候选人能优化从对话帮助到交易结果的完整漏斗。

来源事实

  • TripGenie 将推荐与行程直接连接到机票、酒店和其他旅行产品预订。
  • 官方使用回访、停留时间和订单转化衡量 AI 助手价值。

隐含任务

  • 优化从旅行灵感、推荐和行程规划到可预订结果的转化路径。
  • 平衡帮助质量、用户信任与商业推荐效果。

难度驱动因素

  • 不同旅行商品的价格、佣金、决策周期和转化路径不同。
  • 全球用户、多语言和多目的地形成显著市场差异。
  • 推荐质量与商业转化相互影响，错误引导会损害长期信任。

需要避免：避免用商业排序牺牲建议可信度，导致短期点击提升但长期留存与转化受损。

软实力

沟通力(7/10)

能力结论：由于需要协调多专业团队且问题经常跨越模型、旅行业务和交易系统，难度较高，需要候选人能推动复杂问题形成明确决策。

来源事实

  • 岗位需要联动研发、算法和运营团队并独立推进复杂 AI 产品项目。

隐含任务

  • 协调模型效果、产品体验、旅行运营与交易系统的优先级。
  • 用 PRD、原型和验收标准形成跨团队共识。

难度驱动因素

  • 算法、工程、旅行运营和交易团队使用不同目标与评估语言。
  • Agent badcase 常跨多个系统，需要共同归因和排期。

需要避免：避免用泛化 AI 问题代替可定位事实，造成跨团队责任模糊。

难度驱动因素

  • Agent 技术、对话交互和旅行交易模式同时快速演进。
  • 创新必须在实时库存、用户信任和商业结果约束下验证。
  • 全球产品还需处理语言和市场差异。

需要避免：避免追逐新框架而没有明确旅行任务、用户价值和风险验证。

难度驱动因素

  • 岗位承担产品架构和最终落地的完整结果责任。

需要避免：避免同时铺开全部 Agent 能力却没有关键路径、验证顺序和清晰验收门槛。
